07 · Architecture

RL1 network, contracts and message flows

The technical design behind ORBIT. Network parameters marked “scenario” are assumptions for this demo; RL1's published facts (SCE in Luxembourg, permissioned network built from SWIAT's production DLT, its validator set) are taken from RL1's own announcements.
Network parameters
OperatorRegulated Layer One SCE, Luxembourg (cooperative, one member one vote)
HeritageSWIAT's production DLT network, now owned by the cooperative; 50+ transactions, > EUR 700m volume before launch
Access modelPermissioned: member nodes, validator nodes, read-only supervisor nodes (BaFin, FMA, CNMV, AMF … on request)
ExecutionEVM-compatible (scenario: Solidity contracts, account model)
ConsensusBFT validator consensus with immediate finality, no forks (scenario)
Block time≈ 2 s (scenario)
FeesNo gas market; cost allocated through cooperative membership (scenario)
PrivacyNo personal data on-chain; pseudonymous addresses; identity mapping held by registrars and custodians
InteroperabilityPontes adapter (Eurosystem), Seturion matching engine, registrar back-offices via node APIs

Who runs what
  • Seturion: matching engine (off-chain) + settlement node holding SETTLEMENT_ROLE keys
  • Registrars: nodes plus a register back-office (identity mapping, golden copy, reconciliation)
  • OeKB CSD: node connected to its CSD system and T2S
  • Cecabank: book-building system, agency and paying-agent engine
  • Custodians: wallet infrastructure (HSM/MPC) for client positions
